# Enchantment 281: восстановление категорий случайных свойств

Проверено и применено к рабочей world DB 2026-11-08. SQL:
`sql/updates/world/2026_11_08_00_restore_random_enchantment_types.sql`.
Изменены только категории 84 существующих записей; все 29 723 строки,
ID и веса сохранены. Core и условия логирования не менялись, пересборка
для этой миграции не требуется.

## Причина и источники

`Item::GenerateItemRandomPropertyId` выбирает запись из пула с категорией
`Property=0` либо `Suffix=1` и проверяет соответствующий DBC store.
ID 281 — **of the Feverflare** в `ItemRandomSuffix.dbc`; такого ID в
`ItemRandomProperties.dbc` нет. Запись попала в property-пул 460,
поэтому, например, создание Ivycloth Tunic (9791) могло возвращать 0:
предмет оставался без случайного свойства, а сервер записывал ошибку.
ID 288 (**of the Stormblast**) имеет ту же ошибку категории.

Доказательства сверены до применения:

- Локальные `ItemRandomProperties.dbc`, `ItemRandomSuffix.dbc` и
  `SpellItemEnchantment.dbc` из `loa-runtime/Data/dbc`; проверены WDBC
  заголовки, размеры, уникальность ID и ссылки на эффекты.
- Реальные тела `LoadRandomEnchantmentsTable`, `GetItemEnchantMod` и
  `Item::GenerateItemRandomPropertyId`, значения enum в `ItemEnchantmentMgr.h`,
  а также ссылки `item_template.RandomProperty/RandomSuffix`.
- База `world_548_20240722.sql` из handoff-окружения содержит все те же
  84 неверно классифицированные записи с теми же весами. Ошибка унаследована,
  а не вызвана последними изменениями движения.
- [MaNGOS Four Database, фиксированный commit 8b798ac6](https://github.com/mangosfour/Database/blob/8b798ac6a6a51c0c00c7e20c0a864793eb53904c/World/Setup/FullDB/item_enchantment_template.sql)
  подтверждает все 49 обычных property-записей и их веса в положительных
  пулах 460/461. Отрицательные пулы этого источника тоже содержат смешанные
  данные: целиком они не переносились. Принадлежность суффиксов сверена
  отдельно с локальными DBC и шаблонами предметов.
- [SkyFire, исправление 2026_08_20_world_08.sql](https://github.com/ProjectSkyfire/SkyFire_548/blob/6f000f1878c547f04680cd7c269388a245132ff2/sql/old/5.4.8/world/SFDB_release_26.001_to_27.001/2026_08_20_world_08.sql)
  также затрагивает смешение property/suffix. Его массовое удаление записей
  по отсутствию в suffix DBC не перенесено: оно не сохраняет два пространства
  ID нашей схемы и могло бы удалить действительный контент.

До исправления были 63 ссылки на отсутствующие ID соответствующего DBC
(26 property, 37 suffix). Ещё 21 неправильно классифицированная запись
проходила такую проверку: числовые ID существуют в обоих пространствах,
но означают разные эффекты. Например, property 287 означает stamina,
suffix 287 — Wavecrest; property 360–363 — agility, а одноимённые suffix ID
относятся к Fireflash/Feverflare/Undertow/Wavecrest. Поэтому простого удаления
«неизвестных ID» недостаточно.

## Миграция

| Пул | Восстановление | Строк |
| --- | --- | ---: |
| 458 | Суффиксы 272–274: type 0 → 1 | 3 |
| 460 | 25 property: 1 → 0; 8 suffix: 0 → 1 | 33 |
| 461 | 24 property: 1 → 0; 8 suffix: 0 → 1 | 32 |
| 462, 464 | Суффиксы 288–291: 0 → 1 | 8 |
| 463, 465 | Суффиксы 292–295: 0 → 1 | 8 |

Всего 49 записей возвращены в property и 35 в suffix. План содержит
исходные ID, категории и веса. Для каждой группы проверяются наличие
всех запланированных строк, совпадение весов и отсутствие второй записи
с конфликтующим ключом. При несовпадении вся группа пропускается;
посторонние строки сохраняются. Уже исправленные строки поддерживаются,
повторное и частичное применение проверено. Блокировки `FOR UPDATE`
и изменение выполняются в транзакции; вспомогательные таблицы временные.

Исторические веса **не нормализованы**. В частности, суммы suffix 460/461
составляют примерно 200/200.1. Для cumulative-выбора в диапазоне 0–100
это влияет на достижимость вариантов. Исправлена принадлежность к DBC,
но точность распределения и полный набор вариантов конкретной версии
контента этой работой не доказаны. Произвольные новые веса не назначались.

## Проверки и применение

Артефакты: `wow_mop_codex_handoff/tests/enchantment-281-20261108/`.

- MySQL: семь сценариев на временных копиях всей таблицы — восстановление,
  повтор, изменённый вес, конфликт назначения, отсутствующая строка,
  посторонние пользовательские строки и частично исправленная группа.
  Проверено точное равенство всей ожидаемой таблицы и неизменность рабочей.
- Native-тест использует реальные тела загрузчика, выбора и генератора.
  Транспорт SQL, DBC stores, время, логирование и RNG заменены контролируемыми
  адаптерами. Сами ID и эффекты проверяются по настоящим DBC отдельно.
  На старых данных roll=30 для предмета 9791 выбирает 281, возвращает 0
  и регистрирует ошибку; на исправленных выбирает и возвращает 769 без ошибки.
- GCC 15 и Clang с ASan/UBSan: по **440 000 детерминированных выборок** для
  **44 затронутых шаблонов**, без недопустимых результатов. Все 29 723 строки
  ссылаются на существующие ID правильного DBC; отсутствующих эффектов нет.
  Это проверка генерации, не клиентский тест и не новый полный CTest.
- Перед применением сервер был остановлен, online=0; свежая сжатая копия
  одной таблицы проверена чтением, размером и SHA-256. Размер 142 414 байт,
  путь `backup/item_enchantment_template-before.sql.gz` внутри артефактов.
- Рабочая таблица до применения точно совпала с проверенной исходной,
  после — с ожидаемой. `apply-result.json`: 84 изменения type, 29 723 строки,
  ID/веса сохранены. SQL применён вручную; реестр `updates` не изменялся.
- Автономный smoke `loa-enchantment-281-smoke-20261108.service` завершился
  **09:34:08 МСК**, `Result=success`, exit 0. Уже собранный worldserver
  инициализировался за 14 секунд; команда `reload item_enchantment_template`
  повторно загрузила 29 723 определения. `startup-result.json`: passed,
  online=0, worldserver отсутствует, сохранённые предметы без изменений.
  Использованы отдельные конфигурация/порт, отключённые боты и AHBot;
  установленный runtime не заменялся.

Повтор SQL-регрессии после применения использует сохранённый исходный TSV
и создаёт только временные таблицы (доступ к MySQL всё равно необходим):

## Отдельные оставшиеся данные

**Пустая группа suffix 459.** Расширенный native-тест соседних шаблонов
обнаружил у Flickering Handguards 71458 ссылку на `(459,type=1)` без строк.
Эта группа не входит в семь исправляемых; достоверное распределение весов
не найдено. Отказы сохранены в `native-neighbor-scan-{clang,gcc}.{log,json}`,
описание — `remaining-neighbor-issue.json`. Наличие подходящих ID в DBC
само по себе не доказывает состав и вероятности пула.

**Четыре существующих предмета с randomPropertyId=0.** GUID 406001/410943/
434784/448437, entry 14190/6610/71025/14180 соответственно. На момент проверки
они находятся на аукционе, owner=0, buyer=0, lastbid=0. Исходный случайный
выбор восстановить из этих полей нельзя; причина каждого исторического
экземпляра отдельно не доказана. Их записи не менялись, что подтверждено
полным сравнением до/после миграции и smoke. Исправление генератора данных
не добавляет свойства задним числом. Дальнейшее восстановление этих
экземпляров требует отдельного решения.
